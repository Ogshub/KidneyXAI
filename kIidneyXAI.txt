# Final Project Specification

## Project Title

**An Explainable Machine Learning-Based Decision Support Framework for Personalized Kidney Disease Risk Assessment and Lifestyle Monitoring**

Working name: **KidneyCare-XAI**

---

# 1. What are we building?

We are building a **full-stack web-based intelligent decision-support system** for kidney-health risk awareness.

The system combines:

**Machine Learning**
→ estimates kidney disease risk from clinically relevant data.

**Explainable AI / SHAP**
→ explains which input features contributed to the model's prediction.

**Lifestyle Monitoring**
→ allows users to record water intake, exercise, sleep, diet-related habits, weight, etc.

**Rule-Based Recommendation Engine**
→ generates transparent, personalized health-awareness recommendations from the user's reported information.

**Longitudinal Tracking**
→ stores assessments and lifestyle entries so users can see trends over time.

**College Research Study**
→ anonymized students/faculty data will be collected, with institutional permission, to study lifestyle patterns and evaluate the usefulness/usability of the system.

The system is explicitly **not a diagnostic tool**.

---

# 3. Why are we building this?

A conventional ML kidney-disease project generally does:

```text
Patient data
     ↓
ML model
     ↓
CKD prediction
```

The problem is that a prediction such as:

> Risk = 74%

doesn't tell the user:

* Why did the model produce this result?
* Which features mattered?
* What lifestyle factors should they pay attention to?
* What has changed since their previous assessment?
* Are recommendations based on the model or on their lifestyle information?

Our system addresses these questions separately.

Therefore the research isn't simply:

> "Can machine learning predict CKD?"

Instead, our research investigates:

> **How can an explainable ML model be integrated with transparent personalized recommendations and longitudinal lifestyle monitoring to create a practical kidney-health decision-support framework?**

---

# 4. What is unique?

We should be careful with the word **novelty**.

We are **not** claiming that nobody has used:

* Random Forest
* XGBoost
* SHAP
* CKD datasets

for kidney disease.

Those things have already been studied.

Our contribution is the **integrated framework and its evaluation**.

The proposed system combines:

```text
Clinical ML
      +
SHAP Explainability
      +
Transparent Recommendation Engine
      +
Lifestyle Monitoring
      +
Longitudinal Tracking
      +
Real-World User Evaluation
```

The research will evaluate both:

**technical performance**

and

**human usefulness/understanding**.

That is a much stronger research story.

# 5. Our two datasets

We will deliberately use two different datasets.

## Dataset A — Clinical ML dataset

Purpose:

> Train and evaluate the kidney-disease prediction model.

We will select a publicly available, documented CKD dataset containing:

```text
Clinical features
        +
Known CKD outcome
```

The UCI Chronic Kidney Disease dataset is our initial candidate. It contains 400 instances, 24 predictor variables and a CKD classification target.

However, we will inspect available datasets before finalizing the paper's dataset choice.

We will NOT choose a dataset simply because it is popular.

We will consider:

* number of records
* feature quality
* missing values
* target quality
* documentation
* class balance
* relevance to the research question
* reproducibility
* licensing/access

# 13. Risk assessment

We will start with a **binary ML task**:

```text
CKD
vs
Non-CKD
```

This is much easier to support scientifically with available clinical datasets.

The application can present a model-generated risk score.

But we will **not invent arbitrary thresholds** such as:

```text
0–30 = Low
31–70 = Moderate
71–100 = High
```

until we examine the model and calibration.

If we want Low/Moderate/High categories, we will define them using a defensible methodology.

# 17. Recommendation engine

This will be **rule-based**.

Example:

```text
IF exercise is below target
→ Physical activity guidance

IF salty/processed food frequency is high
→ Dietary awareness guidance

IF smoking is reported
→ Smoking cessation guidance

IF frequent painkiller use is reported
→ Encourage discussion with a healthcare professional

IF hypertension is reported
→ Blood-pressure monitoring/appropriate professional follow-up
```

The exact health guidance will be based on reputable sources.

We will not invent medical prescriptions.

# 43. What we will NOT claim

We will not claim:

> “The model diagnoses CKD.”

We will say:

> “The model estimates CKD risk/classification based on the selected clinical dataset.”

We will not claim:

> “Exercise reduced kidney disease risk by 20%.”

We will say:

> “The user's tracked lifestyle behavior changed.”

We will not claim:

> “SHAP proves creatinine causes CKD.”

We will say:

> “Creatinine contributed strongly to the model's prediction.”

This language matters in the paper.

---

# 44. Research limitations

We'll explicitly discuss:

* dataset size
* dataset representativeness
* possible class imbalance
* self-reported college data
* absence of clinical validation
* absence of prospective medical outcomes
* external validation limitations
* model probability/calibration limitations
* recommendation rules are decision-support guidance, not clinical prescriptions

Being honest about limitations actually makes the research more credible.
